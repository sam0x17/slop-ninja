# Subtensor runtime 486 surface

This is the chain surface Slop Ninja's owner, coordinator, validators and miners
use at Subtensor runtime spec 486. It comes from live testnet metadata,
compared with the metadata rtao ships for spec 482 (main) and spec 484
(unpushed rtao commit `36ffc503`). The subnet netuid is configuration and is
not part of this reference.

Machine-readable outputs are in
[`subnet/fixtures/runtime-486/`](../subnet/fixtures/runtime-486/):

- `needed-486.json` is the compact table: runtime identity, metadata hashes,
  pallet indices, needed calls with origins, storage, events, extensions and
  per-comparison status.
- `surface-testnet-486.json` is the full extracted surface: every call of every
  pallet, digests of all storage entries, events, errors and constants, runtime
  APIs, and signed and transaction extensions.
- `diff-finney-484-testnet-486.json` and `diff-finney-482-testnet-486.json`
  are the surface diffs.

`testnet-486.v15.scale` is the raw V15 blob (SHA-256 `582b1d05…1a81`,
byte-identical to rtao's vendored Finney 486 V15). The adapter's live-surface
tests decode and mutate it; it is test data, not an accepted-runtime list. The
V14 and V16 blobs, the RPC responses and `SHA256SUMS` are in ignored
`data/task-roots/testnet/metadata/`.

## Findings

**484 → 486.** The V15 and V16 blobs each differ from rtao's Finney 484 pins in
one byte: the `System.Version` constant (`spec_version` 484 → 486). Every pallet
index, call index, argument type, storage entry, event, error, runtime API and
signed extension is identical. In Subtensor's runtime code, v484 (`5749dbfb`)
to v486 (`72323e13`) changes only the runtime version and a weight charge in the
contracts chain extension `GetStakeAvailabilityV1`. Neither pallet sources nor
`sdk/bittensor-core` change.

**482 → 486.** The diff adds one storage entry, `SubtensorModule.SubnetState`
(the subnet lifecycle state that rtao v484 already reads), plus the version
constant. No needed call, storage entry, event or extension changes. Between
Subtensor v482 and v486, `subnets/weights.rs`, the Drand, Commitments and
AdminUtils pallets, and `sdk/bittensor-core` are byte-identical.
`sdk/bittensor-core` is also identical to the v478 core rtao builds on
(`850f2755`), except for its e2e tests.

**Older testnet pin.** rtao's newest testnet blob is 481. Relative to it, 486
adds three coldkey-swap calls and four storage entries, appends two
`SubtensorModule` errors without renumbering, and changes `Proxy` types. None
of these is a needed item.

`commit_crv3_weights` does not exist at 482, 484 or 486. The timelocked commit
is `commit_timelocked_weights` or `commit_timelocked_mechanism_weights`.

Identical metadata does not establish identical behaviour. Origins, bounds,
rate limits and freeze windows live in runtime code. The origins below come
from the Subtensor v486 source and are not in the metadata.

`NetUid` and `MechId` are newtypes (`u16` and `u8`). `TaoBalance` is a `u64`
newtype. "Owner or root" means the subnet owner's coldkey, subject to the
per-hyperparameter owner rate limit and the admin freeze window at the end of
each tempo, or root, which bypasses both. `surface-testnet-486.json` lists all
98 AdminUtils calls with their indices.

`register` is a legacy alias of `burned_register`: it ignores its block,
nonce, work and coldkey arguments, and the signing coldkey pays the burn.
Fee-free PoW registration is `pow_register` (`Pays::No`), which binds the
signing coldkey into the proof and requires `NetworkPowRegistrationAllowed`
(default false). Burned and PoW registration are toggled separately, and
neither toggle may disable its mode while the other mode is disabled.

The timelocked commit requires `commit_reveal_version` to equal
`CommitRevealWeightsVersion` (default 4). Its size bound depends on
`SubnetEpochConsensus`. Under the default `Yuma` consensus a commit is at most
5,000 bytes (`YUMA_COMMIT_SIZE_BYTES`). Under `Null` the limit is 32 KiB
(`MAX_CRV3_COMMIT_SIZE_BYTES`) divided by the subnet's mechanism count, and
the committing hotkey needs a validator permit.

## rtao 486 support

rtao `b5553a76` (main on 2026-10-30) vendors finalized Finney 477–486 V15 and
V16 metadata; its testnet metadata pins stop at 481. The testnet 486 V15
snapshot recorded here is byte-identical to rtao's Finney 486 V15 (sha256
`582b1d05…1a81`). It advances its parity pin to v486
(`72323e13249c9e25c7e792a2b3c08502c84651d5`) and keeps the core at v478 with
patch `5f2477f5`; timelock encryption (`generate_commit_v2`) and the epoch
schedule are unchanged. Its `COMPAT.md` records no validated spec range, and its
client only logs when a runtime is outside that evidence.

Slop Ninja pinned that revision for M2 and now pins rtao `fa83052d` (tag
`snapshot-2026-11-05.2`), which vendors the same Finney 477–486 metadata and
also records no validated spec range (see
[`subnet/README.md`](../subnet/README.md#rtao-pin)). The adapter has no spec
gate: each signed operation is resolved by name against the live metadata at
every attempt, and only an operation without a type-correct encoding is
deferred (see [`subnet/README.md`](../subnet/README.md#runtime-upgrades)).
rtao's weight scheduler at the current pin composes its calls and reads its
storage through compiled descriptors while the live shape matches and by name
otherwise, and follows the stored commit-reveal tag under any runtime code; the
adapter records the remaining upstream limits as deferrals, and only a storage
item neither path can read stops rtao's finalized observation and recovery. This report
observes one runtime. It certifies nothing, and a later runtime needs no
re-certification. Subtensor main is already at 487 (`8d7f4212`), which, as of
that commit, only bumps the version from v486; re-running this diff when 487
deploys records what changed.

## Reproduce

The extractor is the offline Rust tool `tools/runtime-surface`; it makes no
network calls. Unwrap saved `state_call("Metadata_metadata_at_version", …)` and
`state_getMetadata` responses, then extract and compare:

```sh
B=tools/runtime-surface/target/release/slop_ninja_runtime_surface
cargo build --release --locked --manifest-path tools/runtime-surface/Cargo.toml
$B unwrap raw-rpc/v15.json testnet-486.v15.scale
$B unwrap raw-rpc/v16.json testnet-486.v16.scale
$B surface testnet-486 testnet-486.v15.scale testnet-486.v16.scale > surface-486.json
$B surface finney-484-rtao-v484 484.v15.scale 484.v16.scale > surface-484.json
$B diff surface-484.json surface-486.json > diff-484-486.json
$B provenance testnet https://test.finney.opentensor.ai:443 raw-rpc > provenance.json
$B needed surface-486.json provenance.json diff-484-486.json diff-482-486.json > needed-486.json
```

`provenance` reads the saved responses of `chain_getFinalizedHead`,
`chain_getBlockHash(0)`, `chain_getHeader`, `state_getRuntimeVersion`,
`state_getStorageHash(":code")` and `state_getMetadata`, all at the finalized
head. Shape digests (`*_sha256_16`) are the first 16 hex digits of SHA-256 over
a canonical structural encoding. That encoding records field names, variant
indices and primitive types, so equal digests mean equal encodings.
Runtime-wide enums such as `RuntimeCall` are recorded by name only.
