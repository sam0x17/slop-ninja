# Controlled source-conditioned draft methods

The completed GPT-OSS style pilot produced strict-fidelity defects in all 23
complete final passages. Test two prompt interventions before expanding this
collection: omit the approximate word-count target, and ask for a claim-by-claim
check against the source before returning prose. A requested check is not an
independent fidelity assessment.

Use the same four exposed Train roots and 32 source-review obligations as the
pilot. Preserve the exact input records, source groups, rights and labels.
Generate four conditions in this fixed order: existing prompt, omitted word
target, claim check, both. Use the source-matched profile throughout. Each
condition makes one new attempt per source, for 16 attempts. The existing-prompt
condition must make new calls; old pilot outputs are context for this experiment,
not its control observations. Within conditions, the collector's task-hash order
applies. One stochastic attempt per source/condition cannot establish a reliable
treatment effect; retain order and failures and avoid significance claims.

Keep the same pinned GPT-OSS weights, tokenizer, MLX environment, fixed
2026-09-15 template date, medium reasoning, temperature 0.7, 4,096-token completion
limit and 1,800-second deadline. All conditions use explicit Harmony V2 final
extraction. This format policy accepts repeated analysis messages, preserves
their raw responses, and rejects commentary or tool routing. The old pilot's V1
records remain unchanged. No output is repaired or retried automatically.

The no-target intervention removes only the approximate-count sentence from
the instruction, preserving exact source bytes and every other prompt clause.
The claim-check intervention adds one fixed instruction covering entities and
roles, quantities, event/time relationships, uncertainty, causality, perspective,
unsupported additions and omitted information. Apply it independently of the
word-target condition. Keep the current collector length and source-copy checks;
removing a prompt target does not remove admission limits.

Freeze all 16 requests, plans, binaries and protocol before generation. Reproduce
all 24 prior pilot requests with the new CLI's default policies and original V1
specification, checking exact task identities, requests and run metadata without
model calls. Render the new requests with the installed tokenizer before launch,
inspect the instructions and message boundaries, and verify the source bytes,
template date, token IDs and context headroom. Use only dedicated Studio
loopback processes, concurrency one and no prompt cache. Leave shared services
and the running capacity fits alone.

Read all complete final passages, including rejected outputs, against every
source obligation. Keep incomplete bodies, format failures and source-copy
exclusions separately. Record each obligation as preserved, violated or
unresolved, with omissions, additions, relation changes, tone and readability
notes. Inspect source-relative dates and the cardiac study's injection/assessment
timing explicitly. Preserve ambiguity in the source rather than rewarding an
invented resolution. This is assistant review, not independent human gold.

Compare complete strict-fidelity passes and obligation-level outcomes within
each source across all four conditions. Report execution/completion, copying and
admission separately; never drop failures to improve a rate. Retain the known
model-generation provenance regardless of fidelity. Do not compare style while
claiming that meaning was held fixed unless the review supports that claim.

Make no A or Pangram calls and admit no record to active Train automatically.
The fixed capacity comparison still precedes selection of a new fitting recipe.
This experiment can improve collection methodology; it cannot qualify A, prove
Pangram transfer or establish B editing quality.
